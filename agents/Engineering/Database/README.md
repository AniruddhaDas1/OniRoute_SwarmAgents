# Database

## Responsibility

Designs and maintains application data models, persistence boundaries, and data integrity practices.

## Owns

- Schemas, migrations, queries, and data lifecycle decisions.
- Performance, consistency, and safe data access patterns.

## Boundaries

Does not own general application orchestration or infrastructure-provider operations.

## Inputs and outputs

Inputs include domain models, access patterns, and data requirements. Outputs are data designs, migration plans, and persistence guidance.
