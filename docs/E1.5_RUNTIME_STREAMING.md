# E1.5 Runtime Streaming

Phase `E1.5` of the OniRoute Core v1.2.1 roadmap. Builds on the completed
E1.1–E1.4 Invocation Runtime to add **real, provider-backed incremental
streaming** through the existing `InvocationEngine` — without redesigning the
engine, without a second provider layer, and without a second streaming path.

## Streaming architecture

```
InvocationRequest(streaming=True)
        ↓
InvocationEngine.stream()            # route (UMAL) → authorize (PolicyEngine) → adapter.stream()
        ↓
InvocationRouter / UMAL ModelSelector
        ↓
ProtocolAdapter.stream()
        ↓
REAL provider stream  (OpenAI SSE / Ollama ndjson)
        ↓
StreamChunk  (immutable, one per real provider event)
        ↓
EngineeringWorkerEngine.execute_contract(streaming)
        ↓
partial content buffer  →  final InvocationResponse / EngineeringResult
```

The non-streaming `invoke()` path (E1.2) is untouched. `stream()` is the only
streaming entry point and it always delegates to the adapter's `stream()`.

## Streaming contracts

`runtime/invocation/models.py`:

- `StreamChunk` — immutable chunk for one real provider event. Fields:
  `sequence` (monotonic), `delta` (content), `provider`, `model`, `protocol`,
  `finish_reason`, `usage` (optional), `latency_ms`, `timestamp`, `metadata`.
- `StreamUsage` — optional, provider-supplied token fields. `None` when the
  provider does not report them. Never invented.
- `StreamFinishReason` — `stop`, `length`, `tool_calls`, `content_filter`,
  `error`, `streaming_unsupported`.

`runtime/invocation/streaming.py`: `StreamResponse` (iterable facade) and
`assemble_stream()` (orders chunks, accumulates deltas, captures the last real
finish reason and last real usage). The assembler never synthesizes content.

## OpenAI-compatible SSE lifecycle

`OpenAICompatibleAdapter.stream()` (`runtime/invocation/adapters.py`):

1. Sends the provider request with `stream: True`.
2. Opens the HTTP transport with `HTTPTransport.stream()` (incremental
   `urlopen` response, iterated line-by-line).
3. Parses only real `data:` SSE events; ignores blanks, keepalives (`:`), and
   non-data lines.
4. `data: [DONE]` terminates the loop and yields **no** chunk.
5. Each real event yields a `StreamChunk` carrying the provider's `delta`,
   `finish_reason`, and (on the terminal event) `usage`.
6. The HTTP response is closed in a `finally`.

```
SSE event          → StreamChunk
data: {"delta":{"content":"hel"}}   → delta="hel", finish=None
data: {"delta":{"content":"lo"}}    → delta="lo",  finish=None
data: {...,"delta":{},"finish_reason":"stop","usage":{...}} → delta="", finish="stop", usage
data: [DONE]        → (loop ends, no chunk)
```

No synthetic terminal chunk is generated from `[DONE]`.

## Ollama native streaming

`OllamaAdapter.stream()` parses newline-delimited JSON. Each provider object is
yielded as a `StreamChunk` (`delta` from `message.content`). The provider's
final `done` object yields the terminal chunk carrying `done_reason` as
`finish_reason` and token usage (`prompt_eval_count`/`eval_count`). Empty deltas
contribute no text.

## InvocationEngine.stream()

`runtime/invocation/engine.py`:

- Routes through UMAL (`InvocationRouter` → `ModelManager`), identical to
  `invoke()`.
- Authorizes through `PolicyEngine.authorize` (budgets recorded on allow).
- Dispatches `ProtocolAdapter.stream()`.
- Does **not** call `invoke()`.
- Enriches each chunk with `provider`/`model`/`protocol` from the selected
  `ModelRecord` when the adapter did not carry them.
- If the provider does not implement real streaming
  (`StreamUnsupportedError`), emits a single structured terminal
  `StreamChunk` with `finish_reason="streaming_unsupported"` and `delta=""`
  rather than simulating data.

## EngineeringWorker responsibilities

`runtime/engineering/engine.py` — `EngineeringWorkerEngine.stream_execute_contract`:

- Reuses `InvocationPlanner` (E1.3) and `ResponseAggregator` (E1.3/E1.4).
- Builds each task via the existing `_prepare_task_request`, then copies the
  request with `streaming=True` (StreamingRequest propagation).
- Iterates `InvocationEngine.stream()` in order, accumulating deltas into a
  partial-content buffer.
- **Completion**: assembles the final content, writes the artifact exactly once
  on a clean terminal (no partial certification).
- **Failure**: catches `StreamConnectionError`, preserves already-received
  chunks as diagnostic `partial_content` in `evidence`, emits `STREAM_FAILED`,
  and does **not** write an artifact. No fallback templates are used to mask a
  provider failure.
- **Unsupported**: detects the structured `streaming_unsupported` chunk, marks
  the task failed, records the reason, and does not write.

## Stream events

`runtime/experience/models.py` extends `StreamEventType` with:
`STREAM_STARTED`, `STREAM_CHUNK`, `STREAM_PROGRESS`, `STREAM_COMPLETED`,
`STREAM_FAILED`. Events are immutable, ordered, and bound to a `mission_id`.
The CLI `ExecutionRenderer` renders the lifecycle; a bound `ExecutionEventStream`
is optional so non-streaming callers are unaffected.

## Failure behavior

- Provider stream error (`StreamConnectionError`): partial content retained in
  `evidence.partial_content`, no artifact written, task marked failed,
  `STREAM_FAILED` emitted.
- Unsupported provider (`StreamUnsupportedError`): one structured `streaming_unsupported`
  chunk, failure recorded, no artifact.
- No retries (those belong to E5). No fallback templates to hide failures.

## Accounting behavior

- Real provider usage (`prompt_tokens`, `completion_tokens`, `total_tokens`) is
  carried from the provider's terminal event.
- When the provider emits no usage during streaming, accounting is `0`/absent
  (never fabricated). `StreamUsage` preserves `None` to faithfully record
  absence; the canonical `Usage` normalizes to `0`.
- Cost remains `0.0` (no real cost signal from local providers).

## No-synthetic-chunk rule

`[DONE]` never produces a content chunk. A terminal `StreamChunk` with an empty
delta and a real `finish_reason` is only emitted when the provider itself emits
that terminal event. The test suite explicitly asserts that `[DONE]` yields no
chunk and that the chunk count equals the number of real provider events.

## Testing strategy

`tests/runtime/test_streaming.py` uses offline fake transports that return canned
SSE / ndjson line sequences — no live API keys, no real network calls, no sleeps.
`tests/runtime/test_invocation.py` uses a local `ThreadingHTTPServer` that emits
genuine SSE so the existing router test exercises real parsing. Covered:

1. OpenAI SSE delta parsing · 2. Multiple SSE chunks · 3. Chunk ordering ·
4. `[DONE]` handling · 5. No synthetic terminal chunk · 6. Finish reason
· 7. Provider metadata · 8. StreamingRequest propagation · 9.
`InvocationEngine.stream()` · 10. EngineeringWorker consumption · 11. Partial
content preservation on failure · 12. Stream completion · 13. Stream failure ·
14. ExecutionContext propagation · 15. Accounting propagation ·
16. Unsupported streaming provider behavior · + Ollama native streaming.
