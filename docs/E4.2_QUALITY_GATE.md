# E4.2 Review Finding Analysis & Quality Gate Decision Engine

## 1. Overview

**Phase E4.2** provides deterministic quality gate decision-making based on E4.1 ReviewReport findings.

```
ReviewReport (E4.1)
        ↓
FindingClassificationEngine
        ↓
FindingAggregator
        ↓
QualityGateDecisionEngine
        ↓
QualityGateResult
        ↓
Future remediation phase (E5)
```

## 2. Purpose

E4.2 answers the question:

> "Given the ReviewReport and its findings, exactly what failed, how serious is it, whether the project may proceed, and what remediation category is required?"

E4.2 is **ANALYSIS + QUALITY-GATE DECISION**. It must NOT:
- Perform automatic repair
- Regenerate code
- Retry generation
- Perform self-healing

## 3. Key Concepts

### 3.1 Quality Gate Decision

Deterministic decisions based on findings:

| Decision | Condition | can_proceed |
|----------|-----------|--------------|
| PASS | No findings | true |
| PASS_WITH_WARNINGS | Only WARNING/INFO | true |
| FAIL | ERROR findings | false |
| BLOCKED | CRITICAL findings | false |

### 3.2 Finding Classification

Findings are classified into categories:

- **SECURITY**: Path boundary violations
- **SYNTAX**: Syntax errors
- **STRUCTURE**: Empty files, missing structure
- **CONTENT**: Content quality issues
- **PLACEHOLDER**: TODO/FIXME content
- **DEPENDENCY**: Missing imports/references
- **FILESYSTEM**: File existence issues
- **CONTRACT**: Contract compliance
- **QUALITY**: Code quality
- **CONFIGURATION**: Configuration issues
- **OTHER**: Uncategorized

### 3.3 Remediation Categories

E4.2 determines what KIND of remediation is needed:

- **NO_ACTION**: No remediation needed
- **MANUAL_REVIEW**: Human review required
- **REGENERATE_ARTIFACT**: Full regeneration needed
- **FIX_GENERATED_CODE**: Fix existing code
- **FIX_CONFIGURATION**: Fix configuration
- **FIX_DEPENDENCY**: Fix dependencies
- **FIX_STRUCTURE**: Fix project structure
- **SECURITY_REVIEW**: Security specialist needed
- **BLOCK_RELEASE**: Block release entirely

## 4. Architecture

### 4.1 FindingClassificationEngine

Classifies individual findings:
- Maps `check_type` to `FindingCategory`
- Maps `severity` to `RemediationCategory`
- Severity overrides category for CRITICAL issues

### 4.2 FindingAggregator

Aggregates findings by:
- Severity counts
- Blocking counts
- Category counts
- Unique artifact/file/rule IDs

### 4.3 QualityGateDecisionEngine

Produces decisions:
- Artifact-level decisions
- Project-level decisions
- Evidence chain
- Deterministic hashes

## 5. Multi-Level Decisions

### 5.1 Artifact-Level Decision

Per-artifact quality gate:

```python
{
    "artifact_id": "art-001",
    "decision": "FAIL",
    "can_proceed": false,
    "total_findings": 2,
    "blocking_findings": 1,
    "has_critical": false,
    "has_error": true,
    "affected_files": ["src/main.py", "src/utils.py"]
}
```

### 5.2 Project-Level Decision

Aggregated project decision:

```python
{
    "decision": "FAIL",
    "can_proceed": false,
    "total_artifacts": 5,
    "artifacts_passing": 3,
    "artifacts_with_warnings": 1,
    "artifacts_failing": 1,
    "artifacts_blocked": 0,
    "blocking_artifact_ids": ["art-002"],
    "blocking_rule_ids": ["R005", "R001"]
}
```

## 6. Finding Groupings

E4.2 provides findings grouped by:

- **Artifact**: All findings for each artifact
- **File**: All findings for each file
- **Rule**: All findings for each rule
- **Category**: All findings for each category

## 7. Evidence Preservation

Every decision is traceable to original findings:

```
EvidenceChain:
├── report_reference (review_id, report_id, verdict)
├── finding_summary (counts by severity)
└── decision_result (decision, can_proceed, blocking items)
```

## 8. Usage

```python
from runtime.contracts.e42_engine import QualityGateDecisionEngine

# Analyze ReviewReport
engine = QualityGateDecisionEngine()
result = engine.analyze(report)

# Check decision
if result.can_proceed:
    print("Project can proceed")
else:
    print(f"Cannot proceed: {result.required_remediation}")

# Get detailed breakdown
for artifact_decision in result.project_decision.artifact_decisions:
    print(f"{artifact_decision.artifact_id}: {artifact_decision.decision}")
```

## 9. Determinism

The quality gate is **fully deterministic**:

- Same `ReviewReport` → Same `QualityGateResult`
- No LLM calls for gate decision
- Sorted outputs for consistent ordering
- SHA-256 hashes for verification

## 10. Integration with E4.1

E4.2 reuses E4.1:

- `ReviewReport` as input
- `ReviewFinding` for classification
- `ReviewVerdict` for decision mapping
- `ReviewHistory` for history storage

## 11. What E4.2 Does NOT Do

E4.2 explicitly does NOT:
- Modify or regenerate files
- Perform self-healing
- Retry generation
- Call LLM for decisions
- Bypass frozen contracts
- Create new InvocationEngine

## 12. Future Phases

E4.2 output feeds into:
- E5: Self-healing and remediation
- Manual review workflows
- Release gate decisions
- Audit trails
