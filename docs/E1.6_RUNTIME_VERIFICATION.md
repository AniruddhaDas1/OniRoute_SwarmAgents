# E1.6 Runtime Verification

Phase `E1.6` of the OniRoute Core v1.2.1 roadmap. Verifies and certifies the
correctness of the complete Agent Runtime execution kernel built through E1.5.

This phase is verification-first. It does not redesign the runtime; the only
production code change made was to fix two adapter defects discovered during
verification.

## Verification findings

### Defect 1: Malformed response silently became empty success (FIXED)

**Before**: `OpenAICompatibleAdapter.invoke()` and `OllamaAdapter.invoke()`
returned empty `InvocationResponse` when the provider response was malformed
(missing `choices` / `message`). This violated E1.6 acceptance criterion
"No failure may silently become successful generation."

**After**: Both adapters now raise `InvocationError` with a descriptive message.
This is the only production code change in E1.6.

### Defect 2: Fallback satisfies dependency despite task failure (DOCUMENTED)

**Finding**: When an implementation task fails, `EngineeringWorkerEngine`
records the failure in `evidence.failures` but ALSO adds the failed task's ID
to `completed_task_ids`, so a dependent documentation task runs anyway.

**Assessment**: This is the EXISTING E1.3 fallback design (fallback template
content satisfies the dependency). It does not silently convert failure to
success — the failure remains in `evidence.failures`. It is documented as
current behavior, not modified, per the E1.6 rule "Do NOT redesign."

## Interoperability acceptance

**Proved (mocked)**: The same `AgentProfile` / `EngineeringContract` executes
against two different compatible mocked provider adapters without modifying
the agent definition. This is labeled as *mocked interoperability
verification* — real multi-provider compatibility cannot be claimed without
external credentials.

## E1.7 readiness

The runtime kernel is ready to be frozen in E1.7 with these documented
limitations:

1. Only 2 real adapters (OpenAI-compatible, Ollama) — catalog providers are
   not runtime integrations.
2. Only 1 configured model (`local-metadata-placeholder`).
3. No automatic provider-failure fallback in `InvocationEngine` (only
   fallback ordering in ModelSelector + template fallback in EngineeringWorker).
4. Real provider smoke tests are opt-in, not CI-required.
